# Block Blast Solver

Решатель Block Blast с компьютерным зрением в реальном времени. Всё работает локально на Android-устройстве, без root и без интернета.

## Что это

Приложение захватывает экран, распознаёт игровое поле и три фигуры, просчитывает лучший ход и либо **подсвечивает** его (режим «Подсказка»), либо **сам расставляет фигуру** (режим «Решатель»).

## Как это устроено

| Слой | Файлы | Что делает |
|------|-------|-----------|
| Модель | `model/Board.kt`, `model/Piece.kt`, `model/Placement.kt`, `model/PieceCatalog.kt` | Доска 8×8 как 64-битная маска, фигуры как bitmask'и, каталог всех фигур Block Blast |
| Движок | `engine/MoveGenerator.kt`, `engine/BoardEvaluator.kt`, `engine/Scoring.kt`, `engine/Solver.kt` | Генерация ходов, эвристика здоровья поля, beam-search по трём фигурам с учётом комбо |
| Зрение | `vision/GrayImage.kt`, `vision/GridDetector.kt`, `vision/BoardRecognizer.kt`, `vision/PieceRecognizer.kt`, `vision/FrameConverter.kt` | Бинаризация, автопоиск сетки, распознавание занятости клеток и фигур |
| Захват | `capture/ScreenCaptureService.kt` | MediaProjection + VirtualDisplay + ImageReader в foreground-сервисе |
| Управление | `automation/TapAccessibilityService.kt`, `automation/AutoPlayer.kt` | Drag-and-drop через `dispatchGesture` |
| Оверлей | `overlay/OverlayService.kt`, `overlay/OverlayView.kt` | Рисование поверх игры: debug-слой и подсветка хода |
| UI | `ui/MainActivity.kt`, `ui/ProjectionRequestActivity.kt` | Панель управления |

Центральный дирижёр — `core/SolverRuntime.kt`: кадр → зрение → движок → снапшот для оверлея и UI.

## Ключевые решения

- **Никакого OpenCV.** Всё зрение — чистый Kotlin на `IntArray` пикселях. Ноль внешних зависимостей, быстрый старт, простая сборка. При желании OpenCV можно добавить как сменный бэкенд.
- **Цвет не используется.** Игра постоянно меняет темы, поэтому распознавание работает на яркости и локальной геометрии: занятость клетки определяется относительно фона, который оценивается из самого поля (медиана).
- **Движок планирует три фигуры, а играет одну.** Три фигуры видны сразу — солвер просчитывает всю тройку, но выполняет только первый ход, затем перераспознаёт экран.

## Сборка

```bash
./gradlew.bat :app:assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`

Тесты ядра и зрения:

```bash
./gradlew.bat :app:testDebugUnitTest
```

## Обновление в один тап

В приложении есть кнопка **«Проверить обновления»**: она дёргает публичный GitHub Releases,
сравнивает версию и, если вышла новая, сама качает APK и открывает установщик. Настраивать ничего
не нужно — репозиторий публичный.

Релизы: https://github.com/MikoUIT/block-blast-auto-solver/releases/latest

Чтобы выпустить новую версию: подними `versionCode` и `versionName` в `app/build.gradle.kts`
и запусти:

```bash
release-github.bat
```

Скрипт собирает APK, читает версию прямо из бинарника, создаёт тег `v<code>-<name>` и публикует
релиз с APK. Первый запуск заодно создаёт публичный репозиторий и пушит код.

## Установка и обновление через локальную сеть (без GitHub)

Если GitHub недоступен, есть лёгкий сервер раздачи: он отдаёт страничку с кнопкой «Скачать и
установить» и всегда свежий APK. Ноль зависимостей, кроме Node.

```bash
publish.bat          # собрать APK, положить в dist/ и запустить сервер
publish.bat build    # только собрать и положить в dist/
```

Скрипт печатает адреса вида `http://192.168.x.x:8788` — открываешь этот адрес в браузере телефона
(телефон и ПК в одной Wi-Fi сети) и жмёшь кнопку. Порт по умолчанию **8788**, меняется флагом:

```bash
node tools/serve-apk.js --port 9000
```

Если браузер телефона отказывается ставить — разреши установку из этого источника в его настройках.
Если после переустановки телефон ругается на конфликт подписи — удали старое приложение и поставь заново.

## Отчёты об ошибках

Основной путь — **локальный приёмник на ПК**, без токенов и интернета:

```bash
run-servers.bat      # поднять оба сервера: приёмник отчётов (8791) и раздачу APK (8788)
node tools\report-server.js   # только приёмник отчётов
```

Дальше в приложении: напиши комментарий, нажми **«Отправить отчёт»** — телефон отправит JSON на
`http://192.168.0.139:8791/report`, а сервер разложит всё в `reports/<дата-время>/`:
`report.md` (читаемый отчёт), `report.json` и `snapshots/*.jpg`. Файлы можно смотреть прямо с диска.

Резервный путь — **GitHub** (если ПК недоступен). Нужен токен: fine-grained, права **`Issues: write`**
и **`Contents: write`** на репозиторий. Вставляется в поле в приложении, хранится только на телефоне.
Снимки заливаются в ветку `reports` через Contents API (в тело issue они не влезают — лимит 65536
символов), в issue попадают ссылки.

- Логи собираются в памяти (кольцевой буфер, ограничен и по строкам, и по символам) из собственного
  логгера приложения плюс перехватываются краши. Логи других приложений недоступны без root — но все
  нужные нам и так наши.

### Снимки для калибровки зрения

Поверх игры висит кнопка **📷**. Каждое нажатие снимает текущий кадр и раскладывает его на **пять
разных видов** — каждый показывает отдельный этап пайплайна, а не одну и ту же картинку в разной
обработке:

| Вид | Что показывает |
|-----|----------------|
| `colour` | Исходный цветной кадр (тема, цвета, эффекты) |
| `grey` | Яркость — то, на чём работает весь пайплайн |
| `binary` | **Бинаризация адаптивным порогом**: белое = «занято/фигура», чёрное = «фон». Именно это видит распознаватель клеток |
| `binaryFixed` | Та же бинаризация фиксированным порогом (128) — для сравнения, помогает ли адаптивный порог |
| `marked` | Разметка: контур найденной сетки, распознанные занятые клетки, рамки фигур, цифры |

Так сразу видно, **на каком этапе** ломается: не тот порог, не та сетка, или сама логика клеток.

Порядок работы: нажми 📷 несколько раз в разных состояниях игры (разные поля, темы, экраны), затем
«Отправить отчёт» — все снимки (до 8) уйдут в отчёт. Кнопка «Очистить снимки (N)» сбрасывает буфер.

## Использование

1. Открой приложение, выдай разрешение **Оверлей** (кнопка «Оверлей»).
2. Включи службу **Доступ** в системных настройках (кнопка «Доступ») — нужно для режима «Решатель».
3. Нажми **«Начать захват экрана»** и подтверди системный диалог.
4. Сверни солвер и запусти Block Blast. Оверлей будет рисовать поверх игры.
5. Переключай режим «Подсказка» / «Решатель» кнопками в панели.

## Настройка точности распознавания

Пороги лежат в `vision/RecognizerConfig.kt`, `vision/PieceRecognizerConfig.kt` и `vision/DetectorConfig.kt`. Значения очков и эвристик — в `engine/Scoring.kt` и `engine/BoardEvaluator.kt`. Exp-константы (очки за линию, бонусы за мультиклир, множитель комбо) подобраны разумно и легко правятся после наблюдения за живой игрой.

## Статус

- Ядро движка и пайплайн зрения покрыты юнит-тестами (28 тестов), включая синтетические кадры в тёмной и светлой темах.
- Логика проверена на синтетике; точная настройка порогов под конкретный девайс/разрешение делается через debug-оверлей на живой игре.
